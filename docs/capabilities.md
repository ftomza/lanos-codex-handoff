# Наблюдения и возможности OBD

Источник: [GitHub Issue #1](https://github.com/ftomza/lanos-codex-handoff/issues/1),
сессия пользователя от 2026-10-24. Это физическое наблюдение из задачи, а не новый
аппаратный тест Go-программы. Точная модель ЭБУ, версия прошивки адаптера и
совместимость других машин/адаптеров не установлены.

В [уточнении владельца](https://github.com/ftomza/lanos-codex-handoff/issues/1#issuecomment-6383158184)
модель исправлена на **Vgate iCar Pro BLE 4.0 Dual**. Ранее указанная Bluetooth 3.0
была ошибкой в описании модели. Подтверждён Classic SPP на MacBook M3 через
`/dev/cu.Android-Vlink`. Позднее Go probe физически открыл порт, но не получил
ответа на ATZ; успешный обмен через Go пока не подтверждён (см. STATUS.md).
Bluetooth отключался даже при открытом порте без команд; новых ECU-ответов нет.
В новых комментариях владелец подтвердил реальные GATT UUID и ECU-ответы через
BLE на MacBook M3 (ниже). Одновременная работа Classic/BLE не проверена.

## BLE: новые физические наблюдения владельца

Источники: [зажигание, двигатель остановлен](https://github.com/ftomza/lanos-codex-handoff/issues/1#issuecomment-6384173048),
[двигатель работает](https://github.com/ftomza/lanos-codex-handoff/issues/1#issuecomment-6384193400).
Обе серии — по три последовательных connect/query/disconnect без повторного
сопряжения; автомобиль стоял, хост — MacBook M3.

| Канал | Наблюдение |
| --- | --- |
| Устройство | IOS-Vlink |
| GATT service | `000018f0-0000-1000-8000-00805f9b34fb` |
| RX notify (ответы адаптера) | `00002af0-0000-1000-8000-00805f9b34fb` |
| TX write (команды адаптеру) | `00002af1-0000-1000-8000-00805f9b34fb` |

Последовательность при остановленном двигателе: `ATE0`, `ATL0`, `ATSP0`,
`0100`, `ATDPN`, `0105`, `010C`. Во всех трёх: `0100` → `SEARCHING...` /
`41 00 BE 3E B8 11`, `ATDPN` → `A5`, `0105` → `41 05 50` (40°C),
`010C` → `41 0C 00 00` (0 RPM). Первый `ATE0` вернул echo + OK,
остальные — OK; это обычное различие состояния echo.

При работающем двигателе во всех трёх снова получены `BE3EB811` и `A5`:

| Сеанс | 0105 payload | ОЖ | 010C payload | RPM |
| --- | --- | --- | --- | --- |
| 1 | `41 05 4F` | 39°C | `41 0C 0E FC` | 959 |
| 2 | `41 05 4F` | 39°C | `41 0C 0E 9C` | 935 |
| 3 | `41 05 4E` | 38°C | `41 0C 0E D6` | 949.5 |

Средние RPM: около 947.8. Это реальные ECU-ответы, а не только связь с ELM.
Точные CR/prompt/фрагменты уведомлений в комментариях не приведены; таблицы
сохраняют payload и не выдаются за побайтовую фикстуру framing.

BLE теперь приоритетен для MacBook/Android; SPP остаётся альтернативой. Go CLI
поддерживает оба транспорта; его новый физический BLE baseline описан ниже.
Тесты владельца сами по себе не проверяют Go BLE-код, Android,
длительную стабильность, перезапуск двигателя или reconnect после ошибки.

**Температура впуска требует проверки.** Raw действительно `41 0F 00` (−40°C),
затем с 08:36:55.948 / elapsed 298.695s — `41 0F 3C` (+20°C), без дальнейших
изменений. Формула декодирования проверена независимо; причина граничного и
постоянного значения не установлена. Не диагностировать неисправность датчика,
не подставлять молча +20°C и не считать весь этот канал достоверным измерением.
Для speed-density первые пять минут имеют непроверенный вход; постоянные +20°C
тоже требуют независимого подтверждения. Даже один температурный множитель
−40°C вместо +20°C завысил бы оценку массы воздуха примерно на 26% при прочих
равных; это иллюстрация чувствительности, не расчёт расхода этой поездки.

## Исходная SPP-сессия

| Запрос | Ответ без завершающих CR/prompt | Интерпретация |
| --- | --- | --- |
| `ATZ`, `ATI` | `ELM327 v2.3` | Строка самоидентификации; не доказательство происхождения прошивки. |
| `ATE0`, `ATL0`, `ATS0`, `ATH0`, `ATSP0` | `OK` | Адаптер принял настройки echo/форматирования/автовыбора протокола. |
| `0100` | `SEARCHING...`, `4100BE3EB811` | Достоверный bitmap диапазона 01–20. |
| `ATDPN` | `A5` | Автовыбор, ISO 14230-4 KWP2000 fast init. Не идентифицирует модель ЭБУ. |
| `010C` | `410C0000` | 0 rpm; ноль является полученным значением. |
| `0105` | `410576` | `0x76 - 40 = 78 °C`. |
| `010D` | `410D00` | 0 км/ч. |
| `03` | `43000000000000` | В этом ответе нет сохранённых DTC. Не исключает pending/permanent codes. |

Порт в задаче: `/dev/cu.Android-Vlink`; скорость baud не указана. Переключение
зажигания иногда разрывало Bluetooth-соединение. Check Engine на момент записи
задачи не горел. Приведённые ответы не содержат временных меток отдельных команд,
поэтому фикстура не придумывает их.

Точные байты с CR и prompt хранятся в
`internal/elm327/testdata/vgate-2026-10-24.json`. Дополнительные ответы `0120`,
`0101`, `ATRV`, тестовые DTC и ненулевые RPM в тестах — **синтетические** проверки,
а не результаты подключения к этой машине.

Фикстура и новые отчёты отдельно хранят owner-reported модель и источник
уточнения. `adapter` продолжает означать реальную строку `ATI`; она сама по себе
не определяет продуктовую модель. Текущий `transport` — `serial_spp`.

## Bitmap BE3EB811: объявленная поддержка

Установлены PID: `01 03 04 05 06 07 0B 0C 0D 0E 0F 11 13 14 15 1C 20`.

| PID | Сигнал | Факт из физической сессии |
| --- | --- | --- |
| 01 | MIL / readiness / число сохранённых DTC | Go BLE baseline: MIL выключен, stored count 0 (`41010007E1A1`). |
| 03 | Fuel system status (Mode 01, не DTC-команда Mode 03) | Go scan: `41030100`, raw_only. |
| 04 | Расчётная нагрузка | Go scan: 5.098%. |
| 05 | Температура ОЖ | Go scan: 31°C; исходная SPP-сессия: 78°C. |
| 06 / 07 | Кратко-/долгосрочная коррекция, банк 1 | Go scan: 0% / −10.15625%. |
| 0B | MAP | Go scan: 41 kPa. |
| 0C | Обороты | Go scan: 936.5 RPM; исходная SPP-сессия: 0 RPM. |
| 0D | Скорость | Go scan: 0 км/ч. |
| 0E | Угол опережения | Go scan: 4°. |
| 0F | Температура впускного воздуха | Go scan: 17°C. |
| 11 | Дроссель | Go scan: 0%. |
| 13 | Наличие кислородных датчиков | Go scan: `411303`, raw_only. |
| 14 / 15 | Кислородные датчики 1 / 2 | Go scan: по 0.455V; единичные чтения. |
| 1C | Соответствие стандартам OBD | Go scan: код 1. |
| 20 | Bitmap следующего диапазона | Python и Go BLE: `41 20 C0 00 00 00`. |

В диапазоне 01–20 **не объявлены** PID
`02 08 09 0A 10 12 16 17 18 19 1A 1B 1D 1E 1F`.
В частности, MAF (`10`) этой сессией не поддержан. Эти PID probe не запрашивает.

Поздний BLE-замер агента: `0120` → `41 20 C0 00 00 00`. В диапазоне 21–40
объявлены только `21` и `22`; Go scan получил `41210000` / `41220000`, raw_only.
Уровень топлива `2F`
в этом bitmap **не поддержан**. Бит продолжения `40` сброшен, поэтому `0140`,
напряжение ЭБУ `0142` и расход `015E` не запрашивались; их поддержка цепочкой
bitmap не объявлена. Значения выше диапазона 40 не измерялись.
Наличие MAP/IAT/RPM в bitmap ещё не доказывает пригодность или точность топливной
оценки M6. Никаких выводов о поворотниках, освещении или прочих кузовных сигналах.

`ATRV` — напряжение, измеренное адаптером, не значение аккумулятора от ЭБУ.
В исходной Issue #1 ответа нет, но агент позднее прочитал через BLE три ответа:
`11.0V`, `10.9V`, `11.0V`, при подтверждённом работающем двигателе
(`010C` → `41 0C 0D 43`, 848.75 RPM). Это низко для обычного напряжения зарядки,
но не является доказательством неисправности генератора: требуется независимый
замер мультиметром на клеммах АКБ. Точность адаптера и падение напряжения до
диагностического разъёма отдельно не проверялись. Сеанс штатно закрыт.

## Состояния нового отчёта

`support` отделён от результата отдельного чтения (`status`). В новом отчёте
`captured_at` — время получения/декодирования полного ответа на Mac, не метка
времени от ЭБУ. Исторические наблюдения из Issue #1 датированы только днём.

- `supported`: PID указан полученным bitmap; это ещё не успешное измерение.
- `unsupported`: бит отсутствует в успешно прочитанном диапазоне.
- `not_yet_tested`: диапазон/измерение ещё не исследован либо bitmap недоступен.
- `temporarily_unavailable`: объявленный PID ответил `NO DATA`, `STOPPED`,
  отрицательным ответом или иной ошибкой; поддержка не сбрасывается.
- `available`: есть валидное декодированное чтение; `raw_only`: есть корректный
  положительный payload, но декодер для него не реализован.
- `invalid_response`: некорректный payload; числовое значение отсутствует.
- `stale`: чтение было получено в неудавшейся сессии; экспортируется без числового
  значения, с сохранением raw/timestamp для аудита.

Каждый новый attempt строит матрицу заново. Предыдущие команды остаются в журнале,
но показания не переносятся в новую сессию. `NO DATA` никогда не становится нулём
или доказательством неподдержки. Пустой список DTC считается подтверждённым только
при `stored_dtcs.status=available` и валидном ответе 43.
