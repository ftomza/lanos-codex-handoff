# M5.5 Android Fuel Computer Implementation Plan

> **For agentic workers:** Execute this plan task by task and verify each step.

**Goal** Add the Go fuel computer behavior to the Android dashboard.

**Architecture** Kotlin consumes typed simulator and live readings on a
foreground tick. The local WebView renders fuel data and sends bounded
controls through the existing channel.

**Spec** [M5.5 design](../specs/2026-11-23-android-m55-design.md)

## Global constraints

Use the existing Gradle and Android dependencies, shared dashboard, native
BLE read-only commands and package ID. Keep this milestone on
`feat/android-mvp`.

## Plan

- [x] Add the shared speed-density and interval vectors in
  `internal/fuel/testdata/android-golden.json`. Assert both Go and Kotlin
  against numeric literals with absolute tolerance 1e-9. Include stopped,
  opted-out, expired input and changed generation vectors.
- [x] Implement `FuelInputs`, `estimateFuel` and `FuelComputer.observe`
  with monotonic endpoints. Use the same limits and coverage rules as Go.
- [x] Implement `FuelStore`, Android AtomicFile storage and revision-bound
  `FuelComputer` controls. Test corruption, failed writes, process restart,
  source/config isolation and frozen previews.
- [x] Connect typed live and simulator readings to a foreground tick and
  expose a compact shared fuel view. Test the WebMessage contract and expiry
  under delayed delivery. Exercise confirmation, source separation and
  restart on an emulator.
- [x] Run Android JVM tests, lint, APK assembly and signature verification.
  Run Android JS tests, web tests, Go regression and `make lint`.
  Update the Android guide, plan and status with evidence.

## Review focus

- Unsupported, stale or nonfinite inputs and zero RPM.
- Gaps from frame expiry, reconnects or background and process transitions.
- Durable errors and stale reset/apply requests.
- Fuel freshness after queued delivery and after source switches.
- Access to native controls remains limited to the current local dashboard.
