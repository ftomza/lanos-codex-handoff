# Android M5.1 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Build an offline simulator-only Android debug APK reusing the dashboard.
**Architecture:** Kotlin Activity owns a WebView and a deterministic simulator. A WebMessagePort carries one snapshot at a time, acknowledged by the page. Exact-origin asset interception serves generated copies of existing web assets plus an Android Feed adapter. No HTTP server or JavaScript interface. Lifecycle closes the feed; the existing browser watchdog hides stale values.
**Tech Stack:** Installed JBR 25, SDK 37 / build-tools 36.0.0; AGP 9.5.1 (built-in Kotlin 2.2.10), Gradle 9.6.0, JUnit 4.13.2. minSdk 26 (java.time/platform WebMessagePort), targetSdk 35 (Android 15 target, avoiding Android 16 large-screen forced orientation), compileSdk 37 (installed SDK).
**Spec:** docs/ANDROID_MVP_CODEX.md, M5.1 only, explicitly authorized by owner.

## Global Constraints
- Work in feat/android-mvp; preserve Go behavior, dependencies and private owner files.
- No Bluetooth permissions, BLE code, vehicle access, fuel port, archive APIs or HTTP server.
- SIMULATOR label, null unavailable values, host timestamps and bounded lifecycle resources.
- No INTERNET permission, file/content URL access, unrestricted JavaScript interface or external navigation.
- Only one milestone; record actual test/build/emulator results and stop before M5.2.

## Review Focus
- Late/replaced channel messages cannot revive previous telemetry; test Feed generation fencing.
- Stale/absent source must hide all numbers; test Kotlin phase boundaries and JS watchdog contract.
- Pause/resume cannot leave multiple producers; lifecycle smoke/instrumentation checks.
- Untrusted origins/paths never fall through to network/file loading; test local route policy.
- Generated assets must match original web behavior without claiming fuel/history support; package and UI smoke.
